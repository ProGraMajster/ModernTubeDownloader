# ModernTubeDownloader 1.3.0

## New

### Highlights

- An optional Modern Dashboard joins the existing Classic interface. Both interfaces use the same download queue, LIVE services, History, settings and profile; changing the interface does not create a second collection.
- Batch Import gains an explicit Import & Download workflow and a destination folder for each list. A new organizer matches previously downloaded recordings to URL lists and offers reviewed moves, recovery and guarded undo.
- First-run setup, an upgrade-time interface choice, searchable settings, sixteen interface languages and version-specific What's New make configuration and migration more approachable.
- The changes below are relative to 1.2.1. Downloading, LIVE recording, the browser extension, Web Remote, manual Batch preparation and the verified application updater already existed; this release extends those capabilities.

### Classic and Modern interfaces

- Modern presents Downloads, LIVE, History, Batch Import, Other and Settings in a shared native workspace, with a sidebar, compact action bars, selectable rows, inspectors, status indicators and consistent themed surfaces.
- Classic remains available. New users choose an interface in setup; existing users retain their saved choice until they explicitly change it. Settings can switch the interface later, and the session-only --classic-ui recovery option remains available.
- Modern uses native controls and the existing application services. Page changes, theme changes and shell switches retain canonical jobs and recording sessions rather than creating replacement workers.
- The Other page connects Batch sessions, the organizer, thumbnail tools, recent operations and existing settings/diagnostics actions. It does not simulate completed work or expose decorative actions without a backing operation.

### Batch Import automation and destinations

- Import & Download chains the existing parser, metadata analysis and admission to the canonical download queue. Manual preparation remains available and is the default mode.
- Automatic preparation can follow an explicit file selection, supported multi-file drop or clipboard import. Each file has its own durable session and destination; a multi-file selection is validated before the first session is admitted.
- A list can use a chosen root folder, editable subfolder name and its own accepted destination. The folder is saved with admitted jobs and survives restart/retry independently of later changes to the global download folder.
- Automatic preparation respects the global paused queue. Resuming downloads requires a separate confirmation that also identifies older pending jobs outside the current list. Analysis pause/cancellation and download pause remain distinct actions.
- Progress separates loading, metadata analysis, queue admission, downloading and finalization. Counts, failures, current titles and advisory size/ETA information come from real work; unknown values remain unknown.
- Completion reconciliation runs when the Batch page is closed. Retry reuses the canonical failed job and its ID/destination. Restart restores saved work without silently restarting metadata analysis.

### Organizer for existing recordings and JSON

- Analyze one or more URL lists against a local source folder without moving anything. Review the proposed recordings, destinations, identity evidence, associated files, sizes and SHA-256 values, then explicitly select and confirm the move.
- Identity comes from canonical History/completed-queue records or validated adjacent .json/.info.json metadata. Provider, URL and media ID must agree; matching a title or finding an ID-like filename is insufficient.
- Verified adjacent JSON, supported subtitles, thumbnails, descriptions and chapter sidecars remain associated with the recording. Their original bytes are preserved. A verified central metadata JSON can be copied alongside the moved media while its central original remains intact.
- The organizer updates canonical History FinalPath and completed-queue FinalFile references without replacing record IDs. Raw JSON contents, including historical paths inside those files, are intentionally not rewritten.
- Existing destinations are never implicitly overwritten. Multiple matches, cross-list destination conflicts, incompatible quality/range evidence, active jobs, partial media and LIVE parts require intervention or are excluded.
- Same-volume moves use a non-overwriting rename. Copy-based moves verify the destination hash before removing the source. Durable per-file checkpoints support explicit recovery after interruption and avoid rewriting a large operation manifest after every file.
- Undo verifies destination content and vacant original paths before reversing work. Changed files, blocked stores or collisions stop the operation while retaining recovery evidence. File moves and the two canonical stores are recoverable steps, not a single cross-filesystem transaction.

### First-run setup and upgrade choice

- A resumable six-step native wizard covers language, Classic/Modern, output and temporary folders, download defaults, updates/notifications/tray, and a final summary.
- A separate one-time choice for existing profiles changes interface/update preferences without resetting folders, quality, cookies, queue, History or LIVE data. Existing profile evidence is checked before new-user defaults are considered.
- Draft steps are saved durably. Closing setup does not complete it; explicit Skip remains distinct from completion. Failed saves leave the last committed decision in place.

### Help and What's New

- Help has six practical topics with links to the existing application pages, tools, setup, logs and documentation.
- What's New immediately displays bundled notes for the exact installed version, then asynchronously requests that version's official GitHub Release. It does not use the newest available release as the installed-version changelog.
- A bounded persistent cache, conditional requests and an offline fallback keep notes available when GitHub is unavailable, rate-limited or has not published the tag yet. The window identifies local, GitHub or cached content.
- Remote content is restricted to safe text, headings and lists; it cannot execute HTML/scripts or load arbitrary images. Official GitHub content is English, with its language fallback identified in other interface languages; bundled notes include English and Polish.
- Later and the window Close button do not mark notes as read. Acknowledgement is stored only after its existing durable save succeeds. Network/cache activity does not acknowledge a version or install an update.

## Improvements

### Downloads and playlists

- Modern's queue inspector presents real metadata, output information and editable options for eligible queued work. Its widgets report observed transfer, storage and process information rather than sample dashboard values.
- Collapsible playlist headers group jobs with validated playlist provenance while preserving canonical job order and identities. Headers show admitted-job counts and status totals; completion means completed jobs, not a fabricated byte percentage.
- Group actions reveal a child, retry failed/interrupted jobs or remove completed queue records through existing operations. Removing a record preserves its media files. Selection remains attached to a real job when a group is collapsed.
- Modern renders at most 40 queue rows per page, including group headers, and reuses compatible visible controls. Classic retains its existing 50-job pages. Group expansion is session-only and begins collapsed after restart.
- The paged playlist preview keeps selection across pages, distinguishes unavailable entries and shows the chosen quality/container in its summary. Existing per-video format resolution and duplicate policy remain authoritative.

### History and large-collection performance

- History no longer builds a card and thumbnail for every stored entry while hidden at startup. Cancellable filtering operates on a canonical snapshot off the UI thread; a page retains at most 40 row controls.
- Modern History adds search, date-range/sort and media-type filters, details and row actions while preserving full-data filtering/export. Paging limits rendered controls rather than removing old records.
- Decoded thumbnail caching uses a 32 MiB budget, at most four concurrent loads and 512-pixel display images. These limits apply to the thumbnail cache, not to the application's entire memory footprint or every native render surface.
- Displayed bitmaps have explicit owners; stale callbacks release their copies, and closing application windows releases owned controls, thumbnail bindings, subscriptions and timers.
- Improvements were developed against isolated large collections, including 2,750 History entries, 2,617 queued jobs, distinct thumbnails and 10,000-entry cases. Those fixtures do not establish performance on another person's computer or certify every physical display configuration.

### LIVE

- Modern LIVE adds active/recent views, source and text filtering, sorting, bounded pages and a structured inspector over the existing session service.
- Details expose recording state, timing, output/part information and the existing session actions. Viewing or selecting a session does not start a recording.
- The independent LIVE scheduler, recording limits, scheduled monitoring, Stop and save, reconnect and verified-part recovery remain shared with Classic. Pausing the VOD queue does not stop LIVE recording.

### Settings and localization

- Search returns specific settings with their category/card context, reveals the selected field and briefly highlights it. Keyboard navigation works through the existing controls. Private field values are not included in the search index.
- Settings, inspectors and setup use measured wrapping/scrolling layouts and the actual viewport at larger logical text sizes. The Modern sidebar no longer gains a horizontal scrollbar merely because application text is set to 200%.
- A shared searchable language picker offers English, Polish, German, French, Spanish, Italian, Brazilian Portuguese, Dutch, Czech, Slovak, Russian, Hungarian, Turkish, Japanese, Korean and Simplified Chinese.
- Locale IDs retain compatibility with earlier English/Polish preferences. Region indicators are local vector artwork; no external image service is required. Resource/key coverage is distinct from complete native-speaker editorial review.

### Updater and data safety

- New profiles default to automatic stable-release checks, verified package download and installation at a safe exit. Existing disabled checks, explicit modes, skipped versions and deferrals are preserved; ambiguous legacy policy requires a choice rather than an automatic opt-in.
- Install at manual foreground startup is a separate optional preference, off by default. Its bounded preflight defers for active work, incomplete Batch/organizer recovery and blocked stores. A per-request commitment prevents an uncommitted/crashed preflight from authorizing installation.
- The existing updater remains responsible for release discovery, official asset validation, SHA-256 verification, staging, wait-for-exit installation, backup and rollback. What's New is a reader of release information, not a second updater.
- Queue, History, LIVE, Batch and nested option models retain compatible unknown JSON fields. Load failures preserve original files and block unsafe writes/admission instead of replacing unreadable collections with empty defaults.
- Onboarding/update preferences publish only committed state. Shutdown still drains remaining process owners if another service's checkpoint fails.

### Integrations and tools

- Thumbnail preview/export uses the existing metadata service and bounded image pipeline, with PNG/JPEG output and recent exports. It reports a saved image separately from a failure to save its recent-operation record, avoiding a misleading overwrite retry.
- Browser handoff, optional consent-based cookie synchronization, NativeHost, Web Remote, notifications and managed yt-dlp/FFmpeg/ffprobe/Deno continue to use their existing services and security boundaries.
- No new browser-store or NuGet distribution is introduced. The framework remains pinned to ModernFormsNext commit 7bf58d06d795d7298c86d9bf9471bbfb46852bab; .NET 10 remains the application runtime.

### Installation and migration from 1.2.1

- Download ModernTubeDownloader-1.3.0-win-x64.zip and its .sha256 from this official release, compare SHA-256, extract the entire archive to a writable folder, and run ModernTubeDownloader.exe. Do not launch it inside the ZIP or mix files from different versions.
- The Windows x64 archive is self-contained and includes the GUI, NativeHost, Updater, license and third-party notices. Symbols are a separate archive. Managed media tools are installed/reused under the existing user profile; they are not bundled inside the application ZIP.
- Existing users can use the application's verified updater. For manual replacement, close the application fully, including the tray and active work, before replacing installation files. Preserve the existing profile and media folders; setup does not require deleting settings, queue, History, Batch sessions or cookies.
- On first foreground launch after an upgrade, complete or defer the applicable interface/update-policy choice. Existing preferences are preserved until an explicit decision commits. Reopen setup or What's New later from the application if needed.
- Switching Classic/Modern is reversible and uses the same data. Moving an installation can require explicit native browser registration repair; it does not grant new cookie permissions.
- The executable is not code-signed. SHA-256 verification checks the downloaded asset against the published checksum; it is not an Authenticode signature or an assurance that Windows will suppress SmartScreen prompts.

## Fixes

### Refresh, focus and presentation

- Batch Import retains visible rows and unchanged workflow/list controls during passive observations and metadata completions. Unchanged progress no longer repeatedly resets the view and closes an open ComboBox. Real progress updates remain enabled.
- A failed Batch journal write refreshes the retained view without inventing a successful commit or admitting another job. Empty queues and lists awaiting analysis no longer show a zero transfer ETA as if unfinished work were complete.
- Informational labels/icons retain their surface color when clicked. Focused editors use an explicit border rather than an unintended solid background. Theme changes refresh read-only Audio/Folder text caches.
- Downloads preserves its open drawer, option draft and widget geometry when a theme transaction reattaches the shell at the same size. Settings retains usable geometry after Classic/Modern reattachment.
- Typography refresh tolerates child controls replaced or reparented by callbacks. Startup update settings no longer alternate intermediate heights through recursive SizeChanged layout, which could cause a native stack overflow.
- Settings search no longer treats Enter used to reveal a result as permission to toggle the newly focused option. Recent tool records publish through the UI dispatcher.

### Transfer-rate reporting

- Download telemetry measures recent observed media-byte deltas using elapsed time instead of presenting a stale cumulative/averaged tool value as the current dashboard speed.
- The chart and summary sample the same canonical byte counter. Counter resets, resumed partial data, terminal transitions and gaps in UI sampling do not invent transfer or draw an uninterrupted historical curve across a missing interval.
- Labels use explicit KiB/s and MiB/s units. This is media payload throughput, so Task Manager's process/network figures can still differ because of sampling intervals, bits-versus-bytes units, protocol traffic and other process I/O.

### Persistence, recovery and installation

- Queue/History/LIVE identity validation no longer invents replacement IDs for damaged persisted records. Interrupted legacy LIVE migration retains original/unknown evidence and rejects conflicting source data.
- JSON reads and atomic publication share a gate for each canonical file path, preventing open-file replacement races on Windows without blocking unrelated stores or profiles. A slow reader no longer delays another store's final LIVE save and admission of the next recording. Canceled waiters and unused gates are released while same-file operations remain serialized.
- Batch recovery preserves a torn final journal append before recovering its valid prefix. Internal journal corruption remains a blocked recovery state. Completed jobs retain their identity after clearing queue records and after restart.
- Organizer matching reports scanned files, identified sources and recordings outside imported lists, and keeps its inspector synchronized with the visible result. An unrelated JSON file does not falsely become proof that a missing URL was downloaded.
- Organizer recovery/undo rejects changed files, occupied paths, active outputs and blocked canonical stores without discarding the last verified copy. History publishes relocated records only after its atomic save succeeds.
- Interrupted or failed journey/update writes do not publish successful choices. Incomplete setup markers are not proof of a new user, and unreadable settings/update state cannot be silently replaced by fresh defaults.
- Update initialization is serialized with policy changes and notifies Settings when a staged package is restored. Rollback continues past unchanged/locked destinations and retains an incomplete recovery journal when restoration cannot finish.

## Known Issues

### Confirmed window-maximization issue

- ModernFormsNext #534 can cause a maximized application window to cover a persistently visible Windows taskbar or show an incorrect strip near it. Use a restored, non-maximized window. Taskbar auto-hide may also help in affected configurations. This known framework issue is accepted for 1.3.0; no framework patch is included. See [ModernFormsNext #534](https://github.com/ProGraMajster/ModernFormsNext/issues/534).

### Qualification limits, not additional confirmed defects

- Some independent native popup/tooltip and focus-sensitive automation scenarios remain NOT QUALIFIED. Earlier interrupted/failed runs are retained; successful targeted cases do not certify every popup or focus transition.
- Physical 5K at Windows 225% DPI is not qualified for this release. Large text tests do not substitute for physical display/DPI testing, and native rendering memory can exceed the bounded thumbnail-cache size.
- A long-duration memory/leak soak was not executed as a release qualification. Short stability runs cannot establish a multi-hour memory plateau or absence of rare leaks.
- The sixteen locale catalogs have structural coverage, but all generated/localized prose has not received complete native-speaker review. Help and bundled release notes supply English/Polish content; official GitHub release text is English with an explicit fallback where applicable.
- Synthetic data and injected I/O/process failures are distinct from real disk removal, physical power loss, every storage device and a private recording collection. No pixel-perfect, all-device, all-source or universal accessibility claim is made.

### Source and organizer boundaries

- yt-dlp extractor availability does not guarantee that every URL, private source or account session works. Service restrictions, authentication/cookie validity, rate limits and upstream changes remain relevant. DRM circumvention is not implemented.
- LIVE FromStart remains experimental/source-dependent, and scheduled monitoring requires the application to keep running. Existing SponsorBlock Remove limitations and stream-copy/keyframe/range restrictions remain; no general transcoding or automatic LIVE-part concatenation is added.
- The organizer needs reliable source identity. Adjacent JSON alone is insufficient, filenames are not trusted as proof, and metadata-only matches cannot establish every requested quality/range. Completed LIVE parts remain excluded until their canonical part references can move together.
- Organizer journals recover recognized interruptions; they do not repair corrupt journal bytes. Partial operation-owned staging evidence is retained rather than silently cleaned up. Concurrent external editing of files being organized is unsupported, and the path checks are not a hostile-process filesystem sandbox.
- Browser extensions remain unpacked integrations rather than a browser-store release. No new NuGet release or code signing is part of 1.3.0.
