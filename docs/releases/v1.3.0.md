# ModernTubeDownloader 1.3.0

**Draft release notes — not published.** The current build identity is
`1.3.0-candidate.1`. Final owner acceptance, exact-commit qualification and separate
publication authorization are still required. This file does not announce availability
or change the stable update feed.

## Interface and first launch

- Optional Modern Dashboard for Downloads, LIVE, History, Batch Import, Other and
  Settings. Classic remains available and both interfaces use the same download,
  LIVE and persistence services.
- Resumable six-step setup, explicit one-time interface choice for existing profiles,
  and an offline What's New screen that can be reopened later.
- Shared language selection with sixteen locale catalogs, searchable names and region
  icons. Complete resource coverage is distinct from native-speaker translation review.
- Bounded queue and History pages, playlist groups, inspectors and actual runtime
  progress/statistics instead of one control per stored task.

## Batch Import and organizing existing recordings

- Manual or one-click import, analysis and queue admission with durable workflow
  phases, list-specific destination folders and idempotent task identities.
- Completion tracking remains active when the Batch page is closed. Interrupted
  journal tails retain their original evidence before recovery.
- Batch presentation updates after real changes and retains existing visible rows.
  Passive observation no longer disables open workflow/list dropdowns or repeatedly
  lays out the whole page.
- An organizer for existing local recordings, with a dry-run, explicit selection,
  verified provider/URL/media identity, associated JSON/subtitle/thumbnail handling,
  canonical History/queue path updates, recovery and guarded undo.
- Ambiguous evidence, changed files, occupied destinations and active/LIVE recordings
  are rejected rather than guessed. Central metadata originals remain available.
  See [organizer safety](../../FILE_ORGANIZER_SAFETY.md) for supported boundaries.

## Data preservation and updates

- Damaged or unreadable queue, History and LIVE stores retain their original contents;
  unsafe writes and work admission are blocked until explicit repair and reopen.
- Failed settings, onboarding and update-state writes do not silently turn failure
  into a completed migration. Shutdown drains remaining process owners even after a
  checkpoint failure.
- Compatible unrecognized JSON fields are retained by the canonical persistence
  models and detached snapshots, including nested download options. Legacy LIVE
  migration preserves unknown source evidence and refuses conflicting evidence.
- New profiles default to automatic stable-release checks, verified download and
  installation on safe exit. Existing preferences, disabled checks and Skip/Later are
  preserved; legacy ambiguous policy needs an explicit choice.
- Installation at manual foreground startup is a separate opt-in, **off by default**.
  Pending work/recovery and prior attempts defer it. Package checksums, external
  updater journals and rollback remain part of the existing update mechanism.

## Limits and acceptance

These notes describe implemented scope, not a declaration that every environment or
provider has been qualified. Final evidence is recorded in the
[readiness ledger](../1.3.0-RELEASE-READINESS.md),
[scenario matrix](../1.3.0-SCENARIO-MATRIX.md) and
[release checklist](../../RELEASE_CHECKLIST.md). Older successful runs qualify only
their recorded source; original failures are retained.

- Visual acceptance against the supplied references belongs to the owner. Functional
  tests do not establish pixel-perfect presentation or complete accessibility review.
- Logical text scaling is not physical Windows DPI qualification. Physical 5K/225%,
  real power/device failure and full native-speaker review remain separately unqualified.
- Synthetic process/file tests are distinct from real provider extraction, media
  probing/decoding and a private user's recording collection.
- Long-duration soak remains deferred by the current testing strategy; short smoke
  tests are not presented as a full soak result.
- The organizer does not relocate completed LIVE part references or guess ownership
  from a filename. See its safety document before organizing legacy collections.
- No new NuGet publication, master merge, stable tag or GitHub Release is implied.

Review the unresolved native popup/focus cases and candidate-specific package results
before finalizing these draft notes for publication. Do not replace them with a broad
"all tests passed" claim.
