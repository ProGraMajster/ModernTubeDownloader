# Modern Downloads playlist groups

Groups are a presentation of canonical queue jobs. A validated HTTP(S) authority and explicit playlist ID, title and positive entry index establish membership. Uncertain provenance and singleton playlists remain ordinary rows. The projection preserves first occurrence and child order without reordering the persisted queue or scheduler. The header counts jobs actually admitted to the queue, including repeat-import deduplication; it does not represent the source playlist's entry count.

The header shows a first-child thumbnail, provider, job-count badge, title, nonzero status counts and explicitly labelled task completion. Its accessible status name and tooltip include all six status buckets. Completion means completed jobs / admitted jobs, not transferred bytes, speed or ETA. Selection remains a canonical child GUID when collapsed. Expand/collapse, Go to job, Retry failed/interrupted and confirmed Remove completed use existing per-job operations. Removal preserves files. There is no invented group-only admission or transfer-pause command.

Modern pages contain at most 40 row controls in total, including group headers. A continued group has one header plus 39 children. Same-shaped pages reuse those visible controls and update their canonical GUIDs, action targets, accessible IDs, image requests and progress. The queue host and unchanged group headers stay attached. No off-page control pool is retained. Structural changes (collapse/expand or a different header arrangement) use the existing detached rebuild; initial native publication still has a measurable cost. Automation clients should resolve current job IDs after paging rather than treating a recycled row reference as a durable job identity.

Grouping is an appearance preference, enabled by default in Modern, persisted independently of queue.json. Expansion is session-only and bounded by currently existing groups; restart begins collapsed. Classic preserves its ordinary 50-job pages and recovery switch. The compact playlist preview retains independent scrolling, selections across pages, explicit checkmarks, unavailable entries and shared options. Its selection summary also shows the selected quality/container without opening those options.

## Native qualification

`scripts/Test-Automation.ps1 -PlaylistGroupsSmoke -PlaylistTransferSmoke` runs the production Windows UIA path with isolated synthetic jobs and FakeTool, including 120/1300-job fixtures, precise second-page GUID/order assertions and five ordinary jobs. `-PlaylistShellSwitchCycles 20` adds a bounded Classic/Modern diagnostic using the same 15-second element lookup budget. Neither uses the Debug automation bridge. Lookup timings and failure-only HWND heartbeat, root geometry, original-resolution PNG and UIA snapshots supplement the existing capture manifest. A later successful diagnostic never changes an earlier failure to PASS.

The historical intermittent missing NavDownloads / stale provider failures are not proven fixed by retaining the queue subtree. Shell switching still replaces navigation chrome and reparents the shared pages. The pinned MFN provider also reports unavailable elements for dispatcher timeouts as well as detached semantic objects, so an unavailable-element exception alone cannot distinguish those causes.
